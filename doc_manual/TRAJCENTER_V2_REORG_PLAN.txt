TRAJCENTER V2 - MODULAR ARCHITECTURE PLAN
=========================================

Goal
----

Reorganize TrajCenter v2 into clear public modules:

- core trajectory model and validation
- file conversion API
- file export API
- ABB robot communication API
- CLI / terminal interface
- RAPID controller-side files

Keep one repository.

Robot communication must be optional.

Conversion and export must remain usable without robot-specific optional
dependencies.

Current rules
-------------

- Do not edit trajcenter/__init__.py manually.
  It is generated by py-init-tools.

- Do not edit generated API pages manually.
  API pages under docs/api are generated by scripts/doc.

- Keep documentation source reorganization for later.
  docs/ is used by MkDocs and generated API/coverage files.
  doc_manual/ can stay temporarily.

- Keep RAPID files in rapid/.
  They are controller-side files and must remain easy to identify.

- Keep operational scripts separate from examples.
  scripts/run_trajcenter_supervisor.py is an operational launch script.
  scripts/examples/ contains example scripts.

- Robot communication must be importable through the public namespace:

    trajcenter.robot.abb

- The historical namespaces are no longer present in this working state:

    trajcenter.converter
    trajcenter.exporter
    trajcenter.rws

- Conversion/export public packages must not depend on robot/RWS modules:

    trajcenter.convert
    trajcenter.export

  must remain robot-independent.

- Robot optional dependencies must remain isolated in the robot optional
  dependency group.

- CLI commands that require robot communication must import robot-specific
  dependencies lazily.

RAPID rules
-----------

- ASCII only.
- Function, variable and constant names below 30 characters.
- Keep RAPID files synchronized with the Python robot API.
- RAPID files remain in rapid/.
- RAPID files are controller-side resources, not Python package modules.
