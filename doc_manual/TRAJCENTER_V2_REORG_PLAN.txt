TRAJCENTER V2 - MODULAR ARCHITECTURE PLAN
=========================================

Goal
----

Reorganize TrajCenter v2 into clear public modules:

- core trajectory model and validation
- file conversion API
- file export API
- ABB robot communication API
- CLI / terminal interface
- RAPID controller-side files

Keep one repository.

Robot communication must be optional.

Conversion and export must remain usable without robot-specific optional
dependencies.

Current rules
-------------

- Do not edit trajcenter/__init__.py manually.
  It is generated by py-init-tools.

- Keep documentation reorganization for later.
  docs/ is used by MkDocs and generated API/coverage files.
  doc_manual/ can stay temporarily.

- Keep RAPID files in rapid/.
  They are controller-side files and must remain easy to identify.

- Keep operational scripts separate from examples.
  scripts/run_trajcenter_supervisor.py is an operational launch script.
  scripts/examples/ contains example scripts.

- Robot communication must be importable through the new public namespace:

    trajcenter.robot.abb

- The historical namespace must remain compatible for now:

    trajcenter.robot.abb

- During migration, tests may remain under tests/rws.
  They can be moved after the robot package is stable.

- Conversion/export public packages must not depend on robot/RWS modules:

    trajcenter.convert
    trajcenter.export

  must remain robot-independent.

Python package roles
--------------------

trajcenter.core
  Shared trajectory model, validation, messages and logging.

  Must not depend on robot/RWS code.

trajcenter.convert
  Public conversion API.

  Exposes converter classes intended for users.

  Must not depend on robot/RWS code.

trajcenter.convert
  Historical conversion implementation namespace.

  Kept for backward compatibility during v2 migration.

trajcenter.export
  Public export API.

  Exposes exporter classes intended for users.

  Must not depend on robot/RWS code.

trajcenter.exporter
  Historical export implementation namespace.

  Kept for backward compatibility during v2 migration.

trajcenter.robot.abb
  Public ABB robot communication API.

  This is the target namespace for robot communication.

  During migration, it may re-export or host code originating from
  trajcenter.robot.abb.

trajcenter.robot.abb
  Historical ABB RWS namespace.

  Must keep working during migration.

  After migration, it should become a compatibility wrapper around
  trajcenter.robot.abb.

trajcenter.cli
  Command line interface.

  Must expose stable commands through:

    trajcenter

trajcenter.ui
  Future terminal UI package.

Detailed STEP 10 options
------------------------

Option A - Facade first, move later
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Pros:

  - Lower risk.
  - Minimal import churn.
  - tests/rws remain untouched.
  - Good if the RWS public API is not fully stabilized yet.

Cons:

  - Implementation remains physically under trajcenter/rws for longer.

Implementation idea:

  trajcenter/robot/abb/__init__.py
    re-exports selected public symbols from trajcenter.robot.abb

  tests/robot/abb/test_public_api.py
    validates the new namespace


Option B - Move implementation now, keep rws wrappers
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Pros:

  - Cleaner architecture now.
  - trajcenter.robot.abb becomes the real home of ABB code.
  - trajcenter.robot.abb becomes clearly legacy.

Cons:

  - More files changed.
  - More imports to update.
  - Higher risk of circular imports if wrappers are not done carefully.

Implementation idea:

  Move:

    trajcenter/rws/_utils.py       -> trajcenter/robot/abb/_utils.py
    trajcenter/rws/constants.py    -> trajcenter/robot/abb/constants.py
    trajcenter/rws/models.py       -> trajcenter/robot/abb/models.py
    trajcenter/rws/reader.py       -> trajcenter/robot/abb/reader.py
    trajcenter/rws/resolver.py     -> trajcenter/robot/abb/resolver.py
    trajcenter/rws/service.py      -> trajcenter/robot/abb/service.py
    trajcenter/rws/store.py        -> trajcenter/robot/abb/store.py
    trajcenter/rws/supervisor.py   -> trajcenter/robot/abb/supervisor.py
    trajcenter/rws/writer.py       -> trajcenter/robot/abb/writer.py
    trajcenter/rws/errors/         -> trajcenter/robot/abb/errors/

  Then replace trajcenter/rws modules with compatibility wrappers:

    trajcenter/rws/__init__.py
    trajcenter/rws/_utils.py
    trajcenter/rws/constants.py
    trajcenter/rws/models.py
    trajcenter/rws/reader.py
    trajcenter/rws/resolver.py
    trajcenter/rws/service.py
    trajcenter/rws/store.py
    trajcenter/rws/supervisor.py
    trajcenter/rws/writer.py
    trajcenter/rws/errors/__init__.py
    trajcenter/rws/errors/base.py
    trajcenter/rws/errors/codes.py
    trajcenter/rws/errors/translate.py

  Wrapper style:

    from trajcenter.robot.abb.models import *
    from trajcenter.robot.abb.models import __all__


Recommended path now
--------------------

Because the project is still under active reorganization and the test suite is
healthy, prefer:

  STEP 10A - Create complete trajcenter.robot.abb facade first.

Then, if tests remain stable:

  STEP 10B - Move implementation from trajcenter.robot.abb to trajcenter.robot.abb
             and leave compatibility wrappers in trajcenter.robot.abb.

This gives one safe checkpoint before the larger file move.
